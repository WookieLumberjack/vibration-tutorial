# vib_tutorial

Real-time teaching app for an N-mass spring-damper chain (PySide6 + pyqtgraph + NumPy/SciPy), managed with uv.

- Run: `uv run vib-tutorial`. Test: `uv run pytest` (GUI smoke test runs headless via `QT_QPA_PLATFORM=offscreen`). pytest runs in up to 4 xdist workers (`addopts`). Each GUI test's windows are freed after it: conftest's `free_windows` (the GUI modules' autouse fixtures) runs `close_graphics`, which also blocks their signals so `gc` freeing a page doesn't call into it half gone, collects, and fails the test if a window it built is still alive or a slot raised (Qt only prints that). A lambda, `partial` or closure over `self` connected to a signal keeps its window for good (PySide holds it as long as the sender, which the window owns): connect a bound method, or `weak.slot(self, lambda self, ...: ...)` (`gui/weak.py`; `tests/test_weak.py` checks `gui/` has none). Drop a window inside a test only after `close_graphics`: freed with its plots still in their scenes, it segfaults. Tests that only build, read or set up pages take conftest's `main_window` (shown, its frame timer stopped). A new lesson page goes in `test_lesson_pages_trials_and_tabs`'s list. The run's summary gives each worker's peak address space (`VmPeak`) and warns past 80 % of `ulimit -v`. Pass `-n0` to debug a test in one process.
- Style: `uv run ruff check` and `uv run ruff format` (config in `pyproject.toml`; the CI's *Lint* workflow checks both, and `cargo fmt --check` and `cargo clippy -- -D warnings` on `native/`). The ignored rules are deliberate (capital matrices, Unicode maths, Qt's camelCase); keep to them rather than adding `noqa`s. The format commit is in `.git-blame-ignore-revs`. Types: `uv run mypy` checks the whole package (the CI too), which is clean: keep it so, with no per-module exceptions. pyqtgraph has no types (it's `Any`). An attribute a page works out later (`self.record = None`) is typed `X | None`, and the code that draws it asserts it's set and why (`assert self.record is not None, "drawn after recompute"`), or a getter makes it (`deriving`'s `_ride()`). `QApplication.instance()` is `theming.application()`, a form's label is `Form.label`, a header's tooltip is `layouts.header_tip`. Don't name a control after a QWidget method (`self.width`, `self.height`, `self.window`): it hides the method from Python callers (`body_width`, `time_window`). What the main window calls on the pages it builds is spelled out as protocols in `main_window.py` (`Themed`, `ChainPage`, `PracticePage`, `SpecPage`). `.pre-commit-config.yaml` runs ruff and mypy before each commit (`uvx pre-commit install`). A dataclass field that `__post_init__` fills in is typed as what it becomes (`ChainSystem.friction`); narrow an Optional with a local and an `assert` saying why it's set.
- `src/vib_tutorial/core/` is NumPy/SciPy with no Qt imports; keep it that way so it stays testable and scriptable.
- Rust kernels live in `native/` (PyO3, abi3), built by maturin (the package's build backend) into `vib_tutorial._native`; `uv sync`/`uv run` rebuild it when the Rust changes. Each kernel replaces a Python function that stays as the reference: `core/native.py`'s `kernel(name, reference)` picks the Rust one when it's built, `VIB_NATIVE=0` runs the Python everywhere, and `tests/test_native.py` compares the two. Name the Python `<name>_reference` and keep the public name for the dispatch (`fluid_bearing.pi_film`). Declare each kernel in `src/vib_tutorial/_native.pyi`, which types the calls for mypy (a test checks it names what the module has); call a kernel class through `core/native.py`'s re-export (`native.LinearSteps`), not `native.module.…`, which mypy can't see into. The release builds' `--smoke-test` fails if the module didn't load.
- `src/vib_tutorial/gui/` holds the Qt widgets. `main_window.py` owns the timer loop and wires the panels to `Simulator`.
- A module's docstring says how it works and, under *Working on it*, what to keep and which tests check it (the rotor's: `core/rotor.py`, `rotor_modes.py`, `rotor_simulator.py`; the films' and the rub's are the simulator's). Read it before changing the module, and keep it up to date there, not here.
- `gui.run()` opens on the course's first page (`open_first_page`, from `links.COURSE`), whose Theory starts with the course map; a bare `MainWindow()` shows the Simulation page, so tests and screenshots build no lazy page. The *Theory window* (`gui/theory_window.py`, Ctrl+F1, built when first opened) shows any page's notes without building the page: `page_html` reads the page module's `NOTES_HTML` or `THEORY_HTML` (or `BACKGROUND_HTML`), so keep a page's Theory in one of those, the same as its tab shows (a test compares them). Its search box indexes those notes' text by section, and `theory/glossary.html` (the *Glossary of symbols*, its first entry) lists the symbols with a `page:` link to where each comes in: add a symbol there when a page brings in a new one. The notes' text lives in `src/vib_tutorial/theory/<module>.html` (packaged by maturin and the spec's `datas`), read by `links.load_notes(name, **parts)`: Qt's rich text plus `<before>` (the page: links to read first) and `<takeaways>` (an `<li>` each), which it writes out, and `<!--PART-->` markers it fills with what the code works out (`trials=trials_html(TRIALS)`, the course map); write new notes there, not in Python strings (a section another page includes gets its own file and a part: `coupling_notation`, `modal_extraction`, `deriving_pendulum`); headings without an anchor get one for its contents tree. Its `page:` links stay in it.
- Units are SI throughout (kg, N/m, N·s/m, m, N, Hz in UI / rad/s internally where named `omega`).
- The simulator uses an exact FOH matrix-exponential discretization. Don't replace it with an explicit integrator, because stiff user inputs must stay stable.
- The main window's pages are a `PageGroups` (`gui/tab_groups.py`): the groups and their order come from `gui/links.py`'s `COURSE`, the order they're meant to be read in (each page uses only ideas from the pages before it). It mirrors QTabWidget's API over the flat order, so `w.pages.setCurrentWidget(page)` works across groups. Theory notes link to each other with `page:<attribute>#<anchor>` (`MainWindow.go_to`); a notes file's `<before>` becomes its "Before this page" line (only earlier pages; `links.before`) and `<takeaways>` its closing list (`links.takeaways`). `tests/test_links.py` checks every link lands on an `<a name>` and every page has both. A page's one-click *Things to try* is a `TRIALS` tuple (the Simulation page's in `gui/sim_trials.py`) whose notes the Theory tab lists too, picked from a `lesson.TrialCombo` (numbered as the Theory's list, keeps the pick shown, a re-pick sets it up again; tests pick by name with `pick`); a trial that changes the chain emits `system_requested` rather than setting it, and `tests/test_tutorial_numbers.py` checks the numbers its note quotes.
- The window fits a 1280 px screen (`test_window_fits_a_1280_px_screen`; 1159 offscreen): it's as wide as its widest page, and a page as its splitter's panes' minimums together. So don't put a long row of controls in a QHBoxLayout (its minimum is the sum of theirs): use `gui/layouts.py`'s `FlowLayout`, which wraps, with `group(...)` keeping a label with its control. Parameter panes and tall panels are `ColumnScroll`s (up and down only, as narrow as their contents allow; give their plots `plot_height`, or they scroll where the plots could have shrunk). A combo box with long items gets `AdjustToMinimumContentsLengthWithIcon`. Build forms with `layouts.form_layout` (fields fill their column: macOS's default keeps them at their size hint, and such a combo then shows a letter or two). Check a layout change with the window at 1280×800, not just 1700×900.
- The *Practice window* (`gui/practice.py`, Ctrl+F2, built when first opened) asks each page's `PROBLEMS` (a tuple next to its `TRIALS`, `core/practice.py`'s `Problem`s; `practice.pages()` finds them in the course's order, importing the page modules without building the pages). A problem's `make(rng)` gives a `Question` with new numbers each time: print its inputs round and work the answer from them as printed, with the page's own `core` functions, so the key can't drift from the page. A number is right within a relative `tolerance` (`check` names the usual slips: 2π, 1000, 2, √2); a choice's options are shuffled by `Problem.question`. `setup` is the page's trial fields, applied by the page's `load_setup` (`SdofTrial("", "", **setup)`): with `predict` it's offered once answered, and checking runs it on the page. Hints link `page:` anchors (opened in the Theory window; a test checks they exist). A *spec* (`goal`, `design`) is answered on the page: the reader tunes its controls and *Check* passes the page's `practice_state()` (its settings as its trial dataclass, so a goal works without the page) to `goal`, which returns `Requirement`s (`at_most`, `kept`: a spec's given numbers must stay put, or moving them would be a way round it); `setup` is where the tuning starts, `design` settings that meet it (a test checks both through the page's boxes, and that the start doesn't). A page with problems has `load_setup` (and `practice_state` for specs), so its trial needs a field for each control they set or read (`TransientTrial.mass`, not a constant in `apply_trial`). Where a page's trials aren't a dataclass (tuples, or presets), a setup dataclass holds what its problems set and read, named by the module's `PRACTICE_SETUP` (`random_vibration.RandomSetup`) so the tests can build its state. The Simulation page is the main window's, so its problems sit in `gui/sim_trials.py` beside its `TRIALS`: `SimTrial` takes a chain element by element (`masses`, `springs`, `dampers`, built by `sim_trials.chain`) and the force (`target`, `freq_hz`, `force`); `MainWindow.apply_sim_trial` sets it up and `sim_practice_state` reads it back. Solved problems are kept in QSettings (`practice/solved`); GUI tests that touch it point QSettings at a temporary directory. `tests/test_practice.py` checks every problem over 50 seeds, and that the short cuts its solutions offer (δ/2π, Δf/2f<sub>n</sub>, 15.76/√δ) pass.
- Lesson pages share `gui/lesson.py` (`plot`, `Form`, `TrialBox`, `RunButton`, `fmt`): a `TRIALS` tuple, tabs drawn only when shown, their own `core/` module and a `tests/test_<module>.py`, their notes' numbers in `tests/test_tutorial_numbers.py`, and listed in `test_lesson_pages_trials_and_tabs`. A page with its own model sets `follows_chain = False`; one that follows the chain sends its trials' chains by `system_requested`. The small ones (the One mass group, Signals & spectra) have no frame loop: a control change works the plots out at once, in closed form or by `sdof.respond` (the exact FOH update, as the chain's). Use `PlotDataItem(pen=None, symbol=…)` for markers on a log axis: a `ScatterPlotItem` ignores the log mode.
- The strip chart (`TimeHistoryPlot`) decimates incrementally: `Decimator` caches each curve's own min/max per bucket (a bucket per pixel column of the plot, so the line covers the pixels the whole record would) by absolute sample number (`History.offset`), and `update_data` gets a `values(index)` callback so only new and decimated rows are derived. If the plotted values of samples already seen change (other curves, a new modal map), go through `set_curves`, which resets the cache.
- The Simulation page's history keeps every stride-th step (`_store_stride`: samples STORE_DT apart, or STORE_PER_PERIOD to the fastest mode's or forcing's period, `Simulator.fastest_hz`, or a tenth of a pulse), continuing the stride across advances (`_carry`). The presets keep every step; a stiff chain's 7.6 µs steps keep every 4th, so the 300,000 samples span ~9 s, not 2.3. Everything recorded per sample (energies, element forces) is worked out only for the kept ones; the energy balance still closes on them.
- `Simulator.advance` caps the number of steps per call (`MAX_STEPS_PER_ADVANCE`). Loop over it for long runs in tests. The Simulation page also caps each frame's steps to its compute budget (`FRAME_BUDGET` over the measured cost of a step, `PROBE_STEPS` while a new system's isn't known), so a test that wants a set stretch of simulated time from `_tick` should call `sim.advance` itself.
- BLAS runs on one thread (`vib_tutorial.main` sets `OPENBLAS_NUM_THREADS` and friends before NumPy loads, and the worker always): the matrices are small, and OpenBLAS's pool made the cracked shaft's frames 6× slower. Measure before letting BLAS thread again.
- A page's motion has one control, `lesson.RunButton` (Start, then Pause / Resume; Space while its page shows, through `panels.space_bar`: a button's own `setShortcut` is reset by `setText`), beside a Reset back to t = 0 at rest. A page that simulates a response (Duffing, Rotor, Gyroscope, the Waves tab, Torsional's start-up, Deriving's release, the mounts' and the frame's forced response) opens at rest and waits for Start; a mode shape swings on its own. A trial (or a practice setup) starts it; a control neither starts nor stops it (a page that relaunches on a change keeps the run state). The Simulation page is the model: its force (Space) is its Start.
- `gui/frame_stats.py` is the frame-timing overlay (`VIB_FRAME_STATS=1`, or a CSV path to log too). Every page's frame loop runs inside `frame_stats.frame(page, sim_t, target_ms)` (free when it's off), and `MainWindow.event` times each repaint; wrap a new frame loop the same way, start its next frame `FRAME_MS` after this one began (not after it ended: that adds the frame's work to every interval), and end it with `gui.settle_plots(page)` (it applies the plots' new ranges in the frame: pyqtgraph defers them to the paint, which then dirties the items and paints every rescaling plot twice). Don't touch a plot's items in a frame where nothing on it changed (the Bode marker at a steady speed): any change repaints its axes and grid. The CSV also has `view` rows (what shows: the tabs picked, a page's `frame_context()`, window size, scale, Hz) and `input` rows (`InputLog`, an app-wide event filter: the control's label and new value); `scripts/frame_report.py` cuts a log at them and summarizes each stretch. Give a new page a `frame_context()` if what it shows isn't in its tabs (the rotor's preset).
- `gui/plot_patches.py` (installed by `make_app`) changes every pyqtgraph plot: a grid is drawn opaque, in the colour its translucent lines would have had over the background, and its axis sits behind the ViewBox so the lines pass under the data (the translucent grid was ~35 ms a frame on a plot that rescales: the Duffing page ran at 20 fps, 47 now). A centred `LabelItem` (a title) wraps to the width it's given instead of setting its plot's minimum width (long titles made plots overflow their view at 1280 px). The patch only reads the label's own state: asking for its parent while a scene is torn down segfaulted. For a marker that moves every frame use `lesson.Dot` (an ellipse moved with `setPos`), not a one-point `ScatterPlotItem` (~0.2 ms a `setData`), and don't re-range a plot each frame for a small change (`OrbitPlots`' `RESCALE`).
- Colours come from the theme in `gui/style.py`, read at draw time through `colors` (`colors.mass[i]`, `colors.force`, `colors.muted`). Don't hard-code a colour: it has to be legible in every theme (`style.contrast` gives the WCAG ratio; aim for 3:1 for curves, 4.5:1 for text). A widget that keeps pens or brushes across redraws needs an `apply_theme()`, called from `MainWindow._restyle`. Mute secondary labels with `theming.mute`, not a stylesheet colour. The first four mass colours stay apart for red-green colour-blind eyes too (no green beside a red), and mode 1 apart from `strong`: `tests/test_style.py` checks every theme.
- To check UI changes, grab a screenshot offscreen: run the script with `QT_QPA_PLATFORM=offscreen` (only the tests set it; without it the window opens on the real display and gets resized by the compositor). Create the app with `gui.make_app("Light")` (or another theme name); `gui.run()` uses the theme last picked, which is stored in the user's settings. This sets Qt's palette and pyqtgraph's background (the default is black). Then build `MainWindow`, resize it to 1700×900 (the README screenshots' size), run the event loop briefly, and `window.grab().save(path)`. Check a change in Light and Dark at least; `MainWindow.set_theme(name)` switches live. The README's and docs/' images come from `scripts/readme_screenshots.py` (saved as 256-colour PNGs, `write_png`, a third of full colour's size); rerun it (or just the affected shots) after a visible UI change and check the captions' numbers still hold (they're in `docs/`).
- The README is the overview and the contents; each course group has a page in `docs/` (`docs/<group>.md`, from `links.COURSE`'s group names) with a `##` section per page in the course's order, plus `the-window.md`, `the-math.md` and `code-layout.md`. A new page gets a section in its group's page and a line in the README's Contents (its summary from `COURSE`); `tests/test_docs.py` checks both, and that every relative link and anchor lands.
- Releases: pushing a `v*` tag that matches `pyproject.toml`'s version runs `.github/workflows/release.yml`, which builds unsigned PyInstaller apps (`packaging/vib-tutorial.spec`) on Linux, Windows and macOS, launches each with `--smoke-test`, and publishes them as a GitHub Release. Build locally with `uv run --group build pyinstaller packaging/vib-tutorial.spec`. If a new feature imports a Qt module, check the spec's `EXCLUDES` and `DROP` lists don't remove it. To try the builds on a branch, `gh workflow run release.yml --ref <branch>` (merges only build when they touch the packaging or dependencies).
- pyqtgraph views left in a scene until interpreter exit can segfault in PySide's teardown (exit 139 *after* pytest prints "passed"). `gui.close_graphics(widget)` tears them down; `gui.run()` and the GUI tests' autouse fixture call it. Check the exit code, not just the summary line.
- Don't let Qt delete a layout item behind PySide's back (e.g. `setParent(None)` on a widget in a layout, which `PlotWidget.close()` does). PySide wraps the items of a filled layout added to another, never learns of the deletion, and a new QObject at the reused address then resolves to the stale wrapper: intermittent segfaults, seen on macOS in `QMenu.addAction`. Take the item out with `layout.takeAt()` first, as `close_graphics` does.
