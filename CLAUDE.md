# vib_tutorial

Real-time teaching app for an N-mass spring-damper chain (PySide6 + pyqtgraph + NumPy/SciPy), managed with uv.

- Run: `uv run vib-tutorial`. Test: `uv run pytest` (GUI smoke test runs headless via `QT_QPA_PLATFORM=offscreen`). pytest runs in up to 4 xdist workers (`addopts`): no window a GUI test builds is ever freed (PySide's signal connections hold them, and deleting them segfaulted), ~20 MB RSS and ~77 MB of address space each, so one process running every GUI test outgrew an 8 GB `ulimit -v`. Tests that only build, read or set up pages use conftest's session `shared_window` and are marked `xdist_group("shared_window")`; `--dist loadgroup` runs that group on one worker and hands every other test out one at a time (xdist's default `load` hands out runs of consecutive tests, and one worker got every GUI smoke test and reached the limit). A new lesson page goes in `test_lesson_pages_trials_and_tabs`'s list, and a new test that builds every page should use the shared window. The run's summary gives each worker's peak address space (`VmPeak`) and warns past 80 % of `ulimit -v`: watch it as pages are added. `tests/conftest.py` caps glibc's malloc arenas at two (`MALLOC_ARENA_MAX`), which the workers inherit: their reserved address space alone put the GUI smoke tests' worker over that limit. Pass `-n0` to debug a test in one process.
- Style: `uv run ruff check` and `uv run ruff format` (config in `pyproject.toml`; the CI's *Lint* workflow checks both, and `cargo fmt --check` and `cargo clippy -- -D warnings` on `native/`). The ignored rules are deliberate (capital matrices, Unicode maths, Qt's camelCase); keep to them rather than adding `noqa`s. The format commit is in `.git-blame-ignore-revs`. Types: `uv run mypy` checks `core/` (the CI too), which is clean: keep it so; `gui/` is read for its types but not reported yet. A dataclass field that `__post_init__` fills in is typed as what it becomes (`ChainSystem.friction`); narrow an Optional with a local and an `assert` saying why it's set.
- `src/vib_tutorial/core/` is NumPy/SciPy with no Qt imports; keep it that way so it stays testable and scriptable.
- Rust kernels live in `native/` (PyO3, abi3), built by maturin (the package's build backend) into `vib_tutorial._native`; `uv sync`/`uv run` rebuild it when the Rust changes. Each kernel replaces a Python function that stays as the reference: `core/native.py`'s `kernel(name, reference)` picks the Rust one when it's built, `VIB_NATIVE=0` runs the Python everywhere, and `tests/test_native.py` compares the two. Name the Python `<name>_reference` and keep the public name for the dispatch (`fluid_bearing.pi_film`). The release builds' `--smoke-test` fails if the module didn't load.
- `src/vib_tutorial/gui/` holds the Qt widgets. `main_window.py` owns the timer loop and wires the panels to `Simulator`.
- `gui.run()` opens on the course's first page (`open_first_page`, from `links.COURSE`), whose Theory starts with the course map; a bare `MainWindow()` shows the Simulation page, so tests and screenshots build no lazy page. The *Theory window* (`gui/theory_window.py`, Ctrl+F1, built when first opened) shows any page's notes without building the page: `page_html` reads the page module's `NOTES_HTML` or `THEORY_HTML` (or `BACKGROUND_HTML`), so keep a page's Theory in one of those, the same as its tab shows (a test compares them). The notes' text lives in `src/vib_tutorial/theory/<module>.html` (packaged by maturin and the spec's `datas`), read by `links.load_notes(name, **parts)`: Qt's rich text plus `<before>` (the page: links to read first) and `<takeaways>` (an `<li>` each), which it writes out, and `<!--PART-->` markers it fills with what the code works out (`trials=trials_html(TRIALS)`, the course map); write new notes there, not in Python strings (a section another page includes gets its own file and a part: `coupling_notation`, `modal_extraction`, `deriving_pendulum`); headings without an anchor get one for its contents tree. Its `page:` links stay in it.
- Units are SI throughout (kg, N/m, N·s/m, m, N, Hz in UI / rad/s internally where named `omega`).
- The simulator uses an exact FOH matrix-exponential discretization. Don't replace it with an explicit integrator, because stiff user inputs must stay stable.
- `core/measurement.py` (virtual modal test) uses the same FOH update, diagonalized into one `lfilter` per eigenvalue so long records are fast (`core/foh.py`'s `FohSteps`, which OMA, random vibration and shock use too: resumable, any number of inputs, stepping z itself where Φ's eigenvectors are near parallel, as a free chain's always are). With friction it steps through `Simulator.drive` instead (~1–7 µs a step in Rust, 20–90 in the Python), so `Acquisition.work(budget)` measures in slices and the page calls it each frame; keep new acquisition code resumable (`yield from` the analog runs).
- Friction's steps (`Simulator.start`, `drive`) run in Rust (`native.FrictionSteps`, one per input kind from `_friction_kernel`, cached in `_friction_cache`), mirroring `_advance_friction_reference`/`_drive_reference` and `_friction_step` event for event, each sub-step's map from `expm_balanced`. Its energy ledger differs in method only: the input's work from an integrator state q = ∫x_k, and the dampers' loss from the energy balance (exactly 0 without dampers), instead of Van Loan's integrals, so an event costs one exponential, not three. The force is open-loop, so `start` works out every step's force first (`_forces`). Keep the two in step; `tests/test_native.py` compares them.
- The Rust kernels release the GIL while they step. `Simulator.advance` is `start` then `collect`: with friction (`steps_aside`), `start` moves the force and the clock, hands the Rust steps to a worker thread and returns; `collect` waits for them and finishes the ledger. Anything that touches `state` (`set_state`, `set_system`, …) waits for them first, and `reset` drops them. The Simulation page starts them as a frame ends, so they run while it paints, and records them at the next frame (`_collect`; it doesn't wait if they aren't done); a system change records them first, under the system they ran with. Without friction the steps hold the GIL, so the page steps them inline and draws them in the same frame. The rotor page steps inline too: its film kernel is ~1 ms of an ~8 ms frame at 1× (drawing is most of it), not worth the threading yet.
- `core/oma.py` (the *Operational modal analysis* page, `gui/oma.py`, which follows the chain): the ambient record drives every mass (or one) with white or low-passed random forces through the exact FOH update, by `FohSteps` with an input per mass (friction left out: OMA needs it linear), run past `settle_time` first so the record is stationary; then FDD (the cross-spectral matrix's SVD per line) and EFDD (the bell's autocorrelation: crossings and log decay), and SSI-cov (`ssi_cov`, the correlations' block Toeplitz SVD at every even order, LSCF's `Stabilization` with shapes, `auto_select` for the poles). An optional sine on m1 (`harmonic_hz`) is a machine running; `harmonics` crosses out a peak whose filtered, shape-projected kurtosis is near a sine's 1.5 and whose damping is nil (a mode with the sine in its band reads low too, but keeps its damping). The *Methods* tab adds `hammer_modes`, the virtual modal test's chain (impact, H1, LSCF + LSFD), measured once per chain when the tab shows. Results go through `identification.match_modes` and the virtual modal test's `ResultsView`. A test checks the record's spectra against H S Hᴴ (S = 2h sinc⁴(fh) for forces linear between samples h apart). The page records again on a test change and only reprocesses on a processing one.
- `core/random_vibration.py` (the *Random vibration* page, `gui/random_vibration.py`, which follows the chain without its friction): a flat band-limited PSD (a force on one mass or every mass, or the base's acceleration in g², the chain then in coordinates relative to the base, −m a_g on each mass), the exact response PSD H G Hᴴ on a grid packed round the modes, its cumulative RMS, and Miles' equation per mode (SRSS). The record's input is synthesized from the PSD (FFT lines, ÷ sinc⁴ for the FOH's linear interpolation) at `OVERSAMPLE` × the band's top, stepped by the FOH update by `FohSteps`. Every `KEEP`-th sample is kept: the response has nothing above the band, so this doesn't alias. Records are sized from the narrowest half-power width (`suggested_duration`, `suggested_block`). An output change only redraws; an input change records again. Its *Statistics* tab (`record_statistics`, `rice`) counts the record's exceedances, crossings and peaks after `upsampled` (a polyphase ×8: 2.5 samples a period can describe the band-limited record but not show its peaks). These sit against Rice's rates from the spectral moments and his peak distribution. The largest peak over a stretch comes from Davenport (independent crossings) and Vanmarcke (clumped, through δ): a test checks Vanmarcke against the record's segment maxima.
- `core/complex_modes.py` (the *Complex modes* page, `gui/complex_modes.py`, which follows the chain): each mode's exact (state-space) shape against the undamped one, `complexity` (MPC, MPD, each entry's angle from the best-fit line) and `compare` (the exact pole beside the proportional approximation's, ζ = φᵀCφ/2ω). The approximation is the chain with C_p = MΦ diag(ΦᵀCΦ) ΦᵀM (`proportional_damping`), so its FRF is the receptance with C_p (`frf_pair`; `frf_grid` keeps off the natural frequencies, where an undamped mode's is infinite). `free_decay` releases the chain in an undamped mode's shape, stepped by expm(AΔ), and reports the modal coordinates. The page's *Chains to try* and *Make it proportional* (c_i = βk_i) load a chain into the Simulation page through `system_requested` (the main window connects it to `params.set_system`). Its *Sweep* tab (`sweep`) follows each mode's exact pole as one damper or spring changes: paired with the undamped modes (MAC) at the first value only, then by continuity (`linear_sum_assignment` on the distance to each track's last pole), since MAC pairing swaps modes once heavy damping has reshaped them; a track is NaN while its mode is overdamped. Its *Identification* tab (`identify`) fits the receptance column on the exact poles with `identification.lsfd` (complex residues) and `real_mode_lsfd` (residues purely imaginary: A/(λ − λ*), A real), errors against the noise-free FRF. Both tabs work out only while they show (`LazyTabs`). `tests/test_complex_modes.py` checks the trials' notes.
- `core/model_updating.py` (the *Model updating* page, `gui/model_updating.py`, which follows the chain): the Simulation page's chain is the structure tested; the page's model is the structure with `Errors` (factors on each mass, spring and damper), so it follows the structure's changes. `measure` takes the structure's modes from `oma.hammer_modes` (the virtual modal test's chain, at the test page's sample rate) or the exact modes with noise, full shapes kept; `Test.with_sensors` picks the sensors without measuring again. `correlate`: the MAC of test shapes (complex) with the model's undamped φ at the sensors, `pair` (best MAC first, `MIN_MAC`), frequency errors against the model's |λ|/2π, the auto-MAC and COMAC. The page measures again only when the structure, the source or the seed changes; the errors and sensors only re-correlate. Updating (`update`): Gauss–Newton on θ = ln p for the chosen `Parameter`s (`updated_errors` multiplies the model's errors by e^θ), the residual (`residual`: relative frequency, then shapes at the sensors realized onto the model's and weighted, then relative ζ) over the correlation's pairs at the start, kept fixed, J by finite differences, Tikhonov λ²‖θ‖², steps clamped (`STEP_LIMIT`), and lstsq with `RCOND` so a direction the data can't see (all masses and springs scaled together) isn't chased. `frequency_sensitivity` is the closed form (strain and kinetic energy shares); a test checks it against finite differences. The *Updating* and *Sensitivity* tabs work out only while they show. Trials reset the seed to 1 so the notes' numbers hold. `tests/test_model_updating.py` checks the trials' notes (the frequency shifts are the exact model's against the structure's; the test's noise is seeded).
- `core/nonlinear_test.py` and `core/force_id.py` (the *Nonlinearity & forces* page, `gui/nonlinear_forces.py`, `nonlinear_page`, after Test planning; follows the chain, its friction included). The page adds one `Element` (a cubic spring or a gap alongside a spring). `stepped_sine` is one-harmonic harmonic balance (`describing`: ¾k₃|D|²D, the gap's `gap_stiffness`, friction (4F/π)V/|V| smoothed below `STUCK`), Newton on Re/Im with a central-difference Jacobian and a line search (friction's near-step makes full steps oscillate; the whole step is taken when no halving helps, or Newton sits in the dip a vanished fold leaves), each step from the last; where it fails or the Jacobian's determinant is negative (the middle branch), the stable solution nearest the last from other starts (`SEEDS`, `RESCUE` iterations) is the jump. `steady_response` is the exact FOH update with the nonlinear forces as an input linear over the step, end value by Newton on the whole state, from harmonic balance's state until a cycle repeats. Force identification: `markov` builds y = Gf from the FOH update (a displacement, or an acceleration with its direct term), `set_up` adds seeded noise and takes G's SVD once; `tikhonov`, `tsvd`, `inverse`, `l_curve` (its corner searched only where the curve moves: below the singular values that matter it stands still and round-off makes false corners), `discrepancy`. The trials set the controls before sending their chain, so the page works out once. `tests/test_nonlinear_forces.py` checks the describing functions by quadrature, every sweep step's residual, the time stepper against `solve_ivp`, G against the FOH simulation, Tikhonov against the normal equations, and the trials' notes.
- `core/test_planning.py` (the *Test planning* page, `gui/test_planning.py`, `planning_page`, after Model updating; follows the chain): sensor placement for the lowest `targets` undamped modes (`undamped_modes`, mass-normalized): `effective_independence` (Kammer: drop the least E_i = [Φ(ΦᵀΦ)⁻¹Φᵀ]_ii, worked out again after each drop; × DPR_i for EfI-DPR; every step kept for the Placement tab), `evenly_spaced`, or by hand (`place`), scored by `quality` (det(Φ_sᵀΦ_s) against every mass's, each mode's noise against every mass's, the auto-MAC). The ODS is X = H(ω)F for a unit force on one mass (`ods`); `ods_parts` splits it into φ_r η_r with the undamped modes' coordinates solved together (ΦᵀCΦ whole), so they add up exactly with any damping. `tests/test_test_planning.py` checks EfI against the determinant it stands for, the parts' sum, and the trials' notes.
- `core/shock.py` (the *Shock spectrum* page, `gui/shock.py`, which follows the chain): a base `Pulse` (classical shapes, or a measured record: `AT_A_MASS`, the chain's absolute acceleration at a mass under a base half-sine through `chain_response`, the exact FOH update by `FohSteps`; or `TRANSIENT`, damped sines in velocity so it ends at rest; noise and offset seeded) sampled by `record` (fs raised so the pulse is a whole number of samples; the input is linear between samples, zero before, a jump at the start a one-step ramp). `srs` steps each oscillator as one complex pole by the same FOH update in closed form (`_foh`; absolute acceleration 2 Re(λ²η)), peaks refined by a parabola, the residual the free decay from the last state over one damped period (its largest value lies there), in `CHUNK`s of oscillators. `bank` spans `LOW`/T to the pulse's `high`/T, widened round the chain's modes; `sample_rate` keeps `PER_PERIOD` samples to its fastest. The pulse's duration comes from the chain (`duration_for`); trials reset the seed to 1. A synthesized pulse (`SINES`, `WAVELETS`; `synthesize`) meets `target` (a plateau above `knee`, ∝ f below, at `SYNTH_Q` whatever the page's Q) by scaling each component by the target over the SRS at its frequency, keeping the best round; its record's length comes from the band (`Pulse.length`, `Pulse.band`), not `duration`. The SRS strays between the components (about 3 dB over the bank, at `SYNTH_PER_OCTAVE` 4 and `WAVELET_MOST` 15; fewer or longer leave deeper dips). `chain_peaks` (the *Chain* tab) puts `base_record` (AT_A_MASS's base half-sine) under the chain, padded RING periods of mode 1: each mode's term φΓ times the SRS at the mode's own f and ζ, combined by ABS/SRSS/NRL, against `chain_response`; with proportional damping the modes' histories add up to it exactly (a test checks). The Chain, Tripartite and Pulse shapes tabs draw only while they show (`LazyTabs`), the chain worked out once per record. `tests/test_shock.py` checks the oscillators against closed forms, `chain_response` against `solve_ivp`, the synthesis, the modal sums, and the trials' notes.
- `core/back_expansion.py` recovers the interior DOFs from the coupled CMS solution; its enhanced recovery adds the interior states to the reduced model's state vector (`RecoveryResponse`), so it shares the same exact FOH step.
- `core/modal_coupling.py` (Modal coupling page) reduces each side of a split to one oscillator per chosen mode. With A's tip modal mass and B's residual mass (the defaults) the 2-DOF model is exactly the Rayleigh–Ritz projection of the chain, and a test checks this. Keep it so, because the page's upper-bound notes depend on it.
- `core/frame.py` (the *Frame builder* page, `gui/frame_builder.py`, last in Building models; its own model, not the chain): a plane `Frame` of `Node`s (u, v, θ each, DOF 3i + d; a `Support` fixes some) and `Element`s (bar, Euler–Bernoulli or Timoshenko beam, spring/damper between nodes or to an `anchor`, torsion spring/damper, point mass), all frozen: editing returns a new frame (`with_node`, `divide`, `without_node` renumbers), so the page's undo is a list of frames. `local(frame, k)` gives each element's own matrices, T and DOFs; `assemble` adds Tᵀk'T over every DOF and marks `fixed` and `unused` (no element touches it: a truss node's θ). `modes` condenses free DOFs without mass exactly (Guyan), and counts mechanisms from K's null space scaled to a unit diagonal (`mechanisms`), not from ω² against the largest: a fine mesh's bending is ~10⁹ below its stretch. Timoshenko's matrices are Friedman–Kosmatka's (φ = 12EI/κGAL²; at φ = 0, Euler–Bernoulli's: a test checks, and the static tip deflection). `member_curve` draws a beam by its Hermite cubics. The canvas (`FrameCanvas`) takes its clicks through `press`/`move`/`release` in view coordinates, so tests build frames without mouse events. The Assembly and Element tabs are rich-text tables (`matrix_html`), drawn only while they show. `tests/test_frame.py` checks the model and the trials' notes. Its forced response is `core/frame_response.py`: a `Load` on one DOF (harmonic, impulse, step), Rayleigh damping from `Frame.zeta` (ζ at the first two modes), and two models as `StateModel`s: `conventional_model` (one oscillator per undamped mode, c_r = φᵀCφ + α + βω², the off-diagonal dropped) and `exact_model` (the state space; massless DOFs without a damper condensed statically, Rayleigh added after, so a proportional frame's two models are the same; a massless DOF with a damper keeps a first-order state, C_dd q̇_d = f_d − C_dm v − K_d q). `formulations` pairs the state space's poles with the undamped modes (MAC plus the frequency's log ratio, `linear_sum_assignment`). `response` steps exactly by stacking the load's own states under A (a constant, or a sine and cosine at Ω), so resonance needs no special case; an impulse is x(0⁺) = BJ. The page works them out only while the Response or Formulations tab, or a damped swing, needs them (`_work`). `tests/test_frame_response.py` checks the FRF against a direct solve, the steps against `solve_ivp`, and the new trials' notes.
- `core/rotor_sweep.py` (rotor page's Bode and polar plots) tracks the 1X vector once per revolution, keyed to the unbalance angle φ, from every simulator step (not the page's decimated history). `RunUpCoastDown.advance` stops each simulator advance at the next stage change, so the legs start and end at the set speeds. The page clears held sweeps when the rotor's parameters change, since the steady-state curve under them changes too.
- `core/fluid_bearing.py` (the rotor page's *Fluid-film bearing* tab) is a plain journal bearing by short-bearing (Ocvirk) theory: equilibrium and the eight coefficients in closed form, in the rotor's axes (x horizontal, y up, load down, spin x → y), with `film_force` by quadrature to check them (tests compare the two). On the rotor (`Bearing.film`, both bearings, the tab's geometry) each film carries `RotorSystem.bearing_loads` (its share of the weight, from statics on the model's own stiffness; the film's own `load` is ignored), is held at ε = 0.9 below `slowest()`, and is linearized about its journal's equilibrium: `_film_terms` gives K_f, C_f and the constant load p = W + K_f q_J, which `gravity_load(Ω)` adds so the journals rest on the locus. The simulator holds p at each chunk's speed, as A(Ω).
- With `nonlinear_films` the simulator steps the films' whole force instead (`whole_films`: on a round shaft; a turning shaft keeps them linear). `pi_film` gives it in closed form with its stiffness, damping and dissipation Ψ (tests check it against `film_force` and finite differences). `RotorSimulator._film_steps` keeps the exact FOH update, with each film's K_f and p but its damping replaced by the bound C_b (`full_film_damping`, the uncavitated film's, taken afresh as the journal moves), and adds the remainder as a load on the journals, found each step by Newton (`_Films.solve`, cut back on the convex Q). Don't put C_f back in the update: near the wall the remainder would be stiffer than the update, the step rings, and the journal is thrown through the wall. The Rust kernel (`native.FilmSteps`, one per held speed and step from `_Films.stepper`) runs `_film_steps_reference`'s loop and takes the bound itself as the journals drift, with its own FOH exponential (`linalg.rs`'s `expm_foh`: Al-Mohy–Higham on the augmented matrix's blocks, balanced first, since A h runs from h to K/M h; more accurate than SciPy's here). ~1.6 µs a step, ~6 µs on Oil whirl, where the journals circle near the wall and the bound is retaken every ~15 steps (the Python: 45–120 µs). Keep the Rust in step with `_film_steps_reference` and `_Films`; `tests/test_native.py` compares them while ramping and through retakes, and the FOH with `foh_discretize`. The step only resolves the spin and the modes coarsely (`FILM_MODE_STEPS`), and the page caps each frame's computing (`step(…, budget)`). Everything else (Campbell, stability, steady states) stays linearized.
- `core/magnetic_bearing.py` (the rotor page's *Magnetic bearing* tab) is an active magnetic bearing: a magnet pair per axis (negative stiffness k_m, current gain k_i, from the gap, bias, pole area and turns) under a PID with a filtered derivative behind a first-order amplifier, `gain(s)` in closed form and `state_space()` per axis (tests check they agree). On the rotor (`Bearing.magnet`) its -k_m is in K and the controllers' states follow q and q' in the state: size states from `system.n_states` (2 n_dof + `n_control`), take velocities as `state[n:2n]`, not `state[n:]`. The steady states add the magnets' k_i G(ikΩ) at each harmonic (`support_stiffness`, `dynamic_solve`); with integral action the 0X row pins the journals at the centre, and the rest state comes from `static_state` (A z + B f = 0). Their slow integrator roots are near-repeated and split by a hair, so `whirl_modes` counts a root with |Im λ| < `OVERDAMPED` |Re λ| as not oscillating, and reports the fastest such growth as `drift` (a magnet too weak for k_m diverges without oscillating); `least_damped` and `growth_rate` use it.
- A stator ring round the disc (`RotorSystem.stator`, a `Stator`; the *Rub* tab, `gui/rotor_rub.py`) is in the time response only: `stator_force` gives the ring's push and smoothed-Coulomb drag with its derivatives, and `RotorSimulator._rub_steps` adds it to the exact FOH update as a load on the disc, linear over the step, solved by Newton (`_rub_solve`), as the films' remainder is. The Rust kernel (`native.RubSteps`, built per call from the chunk's Φ, Γ0, Γ1) runs `_rub_steps_reference`'s loop, `stator_force` and the heat included: ~0.6 µs a step against 10–60 in the Python; keep them in step (`tests/test_native.py` compares them). `step_size` resolves the disc on the ring's mount. Only on a round shaft with the films linearized (`__post_init__` raises; the page drops the ring and disables its checkbox). Campbell, stability and the steady states leave it out. Each advance's `RotorSamples.rub` holds the push; the page's history keeps the largest since the last sample kept (`PUSH`). A forward full rub's steady state is a linear one with the ring as a cross-coupled spring at the disc; a test checks it. With `thermal_gain` the rub's heat (column 3 of `rub`) bows the shaft (Newkirk): `RotorSimulator.thermal_bow`, complex from the mark, held over chunks of at most τ/`THERMAL_STEPS` and moved on by `_warm` (exact first-order lag), loads the shaft as the residual bow does (`bow_load`, in `force`). The page records the spiral (`_record_spiral`) at a steady speed only.
- The rotor's stiffness depends on speed: K + ΩH, with H from the shaft's internal damping and the bearings' fluid swirl (`Bearing.swirl`, k_xy growing as λcΩ) (`RotorSystem.circulatory()`, `speed_dependent`), plus an oil film's K_f(Ω); its damping too, C + C_f(Ω). K itself is not symmetric once a bearing has cross-coupling (`kxy`, `kyx`). Use `system.stiffness(omega)` and `system.damping(omega)` wherever the speed is known, not `matrices()` alone (it leaves the films out). `core/rotor_stability.py` finds the onset speed by sweeping and bisecting the least damped mode's ζ.
- The disc may sit between the bearings or overhang one (`position` > 1 or < 0, never on a bearing). The shaft's nodes come from `RotorSystem._mesh` in axial order, and the 3D view spans `system.extent`, so don't assume the disc is between 0 and L. Presets live in `core/rotor_presets.py`, and `tests/test_rotor_presets.py` checks the numbers in their notes.
- The shaft may have mass (`density` > 0): it is then a beam FE model (`elements`, consistent or `lumped` mass), reduced Craig–Bampton style to the stations plus the shaft's fixed-interface modes up to `MODE_LIMIT` (`RotorSystem._reduced`). So q is `[the 8 station DOFs, ξ_x, ξ_y]`: `XA`…`YB` keep their indices, but q has `system.n_dof` entries. Size arrays from `n_dof` (not 8 or `N_DOF`), split or build the planes with `plane_dofs`/`merge`/`plane_load`, and get the shaft's shape anywhere from `deflection`. M is then full (`mass_inverse`). With density 0 the model is exactly the massless Jeffcott one whatever `elements` is (a test checks); keep it so. Raising `MODE_LIMIT` costs time: the time step resolves the fastest mode kept.
- Everything that turns with the rotor (unbalance, balance weights, disc skew, shaft bow) goes through `RotorSystem.rotating_load(Ω, Ω')`, as f_x + i f_y = P e^{iφ} on [A, D, θ, B]; both the simulator's `force` and `synchronous_response` use it, so the steady state and the time response can't drift apart. A new 1X source belongs there. Two-plane balancing's `plane_weights` (`PlaneWeight`) go there too: on the disc they add to `mass_unbalance` and `couple_unbalance` (a weight at axial offset h adds w·h to the couple); on the shaft each is a point force S(z)ᵀw. The Balancing tab keeps its readings at all four stations, and forgets its trial runs when the planes change, since the influence matrix belongs to them. φ is the keyphasor mark's angle, not the heavy spot's: every rotor angle (unbalance, weights, bow, skew) is measured from the mark, and the heavy spot drawn is `mass_unbalance`'s.
- An asymmetric shaft (`asymmetry` Δ, EI(1 ± Δ), stiff axis at `asymmetry_angle` from the mark) has a stiffness that turns with it: `stiffness(Ω)` is its mean, `stiffness_at(Ω, φ)` the whole thing at an instant. Its modes are Floquet modes (`_rotating_modes`, exact in axes turning with the shaft, on isotropic supports; `_hill_modes` otherwise), its steady states come by harmonic balance (`harmonic_response`: `synchronous_response`'s 1X, `gravity_response`'s mean sag and 2X), and the simulator splits each step around a mid-step kick from the turning part (exact FOH with K held when it stands still). Its criticals are its two axis rotors' (`axis_system`), and `Onset.end` is where its unstable band ends. A round shaft takes none of these paths; tests check that Δ → 0 matches it.
- A cracked shaft (`crack`, a `Crack`) is a hinge at the crack (compliance from `crack_compliance`, by depth), condensed exactly onto the stations (`_hinge_loss`). Breathing, the weight opens it (`crack_sign`, `crack_open(φ)`), so its stiffness has 1X, 2X and 3X; held open it turns with the shaft like the asymmetric one. Both are one Fourier series, `_periodic_terms` (the crack's mean goes in K, the harmonics E_k turn): test `system.periodic`, not `asymmetry`, for anything that turns; `spacing` is 1 for a breathing crack (harmonic balance then couples every harmonic, Hill's method steps by Ω) and `rotating_frame` says when the rotating-frame modes are exact. `steady_harmonics` gives the whole steady state (gravity and 1X loads together, 1X–3X), which the Bode plot and the tracker (`vectors3`) compare. A massless shaft's crack does not depend on `elements` (a test checks).
- Gravity (`RotorSystem.gravity`) only moves the rotor's equilibrium to `static_deflection(Ω)`. Anything that measures vibration (the 1X tracker, peaks, the spectrum, the phase readout) works on `vibration(system, q, Ω)` (`core/rotor_sweep.py`), the motion about it; only the drawing can show the sag (the page's *Static sag* box). On an asymmetric shaft gravity also drives 2X: the sag is then the mean of a periodic motion, and the 2X stays in the vibration.

The closed forms are Lagrange's: the spin and the vertical momentum conserved, the tilt in an effective potential, its turning points the roots of a cubic in cos θ (`Motion.roots`: cos θ₀ is one, divided out, the quadratic left solved exactly), the nutation period an elliptic integral, the mean precession by Gauss–Legendre, the path (waves, cusps, loops) from φ' at the turning points, and the two steady precession rates. `TopSimulator` steps the whole body, not the Euler angles (singular upright): a unit quaternion and L in space, Strang-split into gravity's moment over half steps (exact: it depends on the orientation alone) and the free symmetric top over a whole step (exact: about L at |L|/I₁ and about its axis), so it is symplectic and second order, both momenta are kept to round-off, and the step only has to resolve the free wobble (`PER_PERIOD` a turn), not the spin; ~1.5 µs a step in plain Python floats. `euler_reference` (the Euler-angle equations by `solve_ivp`) is for the tests. - Colours come from the theme in `gui/style.py`, read at draw time through `colors` (`colors.mass[i]`, `colors.force`, `colors.muted`). Don't hard-code a colour: it has to be legible in every theme (`style.contrast` gives the WCAG ratio; aim for 3:1 for curves, 4.5:1 for text). A widget that keeps pens or brushes across redraws needs an `apply_theme()`, called from `MainWindow._restyle`. Mute secondary labels with `theming.mute`, not a stylesheet colour. The first four mass colours stay apart for red-green colour-blind eyes too (no green beside a red), and mode 1 apart from `strong`: `tests/test_style.py` checks every theme.
- To check UI changes, grab a screenshot offscreen: run the script with `QT_QPA_PLATFORM=offscreen` (only the tests set it; without it the window opens on the real display and gets resized by the compositor). Create the app with `gui.make_app("Light")` (or another theme name); `gui.run()` uses the theme last picked, which is stored in the user's settings. This sets Qt's palette and pyqtgraph's background (the default is black). Then build `MainWindow`, resize it to 1700×900 (the README screenshots' size), run the event loop briefly, and `window.grab().save(path)`. Check a change in Light and Dark at least; `MainWindow.set_theme(name)` switches live. The README's and docs/' images come from `scripts/readme_screenshots.py` (saved as 256-colour PNGs, `write_png`, a third of full colour's size); rerun it (or just the affected shots) after a visible UI change and check the captions' numbers still hold (they're in `docs/`).
- The README is the overview and the contents; each course group has a page in `docs/` (`docs/<group>.md`, from `links.COURSE`'s group names) with a `##` section per page in the course's order, plus `the-window.md`, `the-math.md` and `code-layout.md`. A new page gets a section in its group's page and a line in the README's Contents (its summary from `COURSE`); `tests/test_docs.py` checks both, and that every relative link and anchor lands.
- Releases: pushing a `v*` tag that matches `pyproject.toml`'s version runs `.github/workflows/release.yml`, which builds unsigned PyInstaller apps (`packaging/vib-tutorial.spec`) on Linux, Windows and macOS, launches each with `--smoke-test`, and publishes them as a GitHub Release. Build locally with `uv run --group build pyinstaller packaging/vib-tutorial.spec`. If a new feature imports a Qt module, check the spec's `EXCLUDES` and `DROP` lists don't remove it. To try the builds on a branch, `gh workflow run release.yml --ref <branch>` (merges only build when they touch the packaging or dependencies).
- pyqtgraph views left in a scene until interpreter exit can segfault in PySide's teardown (exit 139 *after* pytest prints "passed"). `gui.close_graphics(widget)` tears them down; `gui.run()` and the GUI tests' autouse fixture call it. Check the exit code, not just the summary line.
- Don't let Qt delete a layout item behind PySide's back (e.g. `setParent(None)` on a widget in a layout, which `PlotWidget.close()` does). PySide wraps the items of a filled layout added to another, never learns of the deletion, and a new QObject at the reused address then resolves to the stale wrapper: intermittent segfaults, seen on macOS in `QMenu.addAction`. Take the item out with `layout.takeAt()` first, as `close_graphics` does.
